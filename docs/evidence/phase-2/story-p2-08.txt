## decisions (the spec-silent points this story had to settle)

1. **Where the detail header's status comes from.** `GET /api/quests/:name` answers the *bare*
   quest object (D49) — it carries no status — so the header reads the browse list's own row
   through the shared `QUESTS_QUERY_KEY` cache instead of a second status contract. That key
   already applies D49's `extracted` default, is invalidated by every save
   (client/src/pages/ExtractionPage.tsx:198), and is usually already cached from the list the
   user just came from. A missing row or a failed list read degrades the badge to `extracted`
   and never blocks the page (`questStatus(undefined)`).
2. **`aria-disabled="true"`, never the `disabled` attribute**, on both Edit buttons: a natively
   disabled button is dropped from the tab order and does not reliably fire the native `title`
   tooltip, so the control would neither explain itself nor be reachable. There is no tooltip
   primitive to use — D39 ships only the primitives the shell needed. Measured consequence for
   the specs: Playwright's disabled check consults `getAriaDisabled`, so `toBeDisabled()` passes
   on these buttons and `click()` refuses to act on them; the no-navigation assertions therefore
   use `dispatchEvent('click')`, which fires the real DOM event.
3. **The status-menu placeholder is p2-09, not Phase 3.** Task 2.8 is story **p2-09**, still
   inside Phase 2, so the Actions column's second button says "Status transitions arrive with
   story p2-09" rather than borrowing the Edit button's Phase 3 sentence. p2-08 must not
   implement transitions; a visually marked (dashed border), documented placeholder is the
   smallest honest thing to ship in its place.
4. **`emptyStateMessage('All')` is "No quests found."** The spec's template (L268) is
   `No {status} quests found.`, which for the one tab with no status would read "No All quests
   found.". The other three are the template verbatim.
5. **`[Wrap]` is deliberately not shipped.** The spec's `[Copy] [Wrap]` diagram (L336) comes
   from the `@monaco-editor/react` option of L326, where wrapping is a toggle;
   `react-json-view-lite` wraps unconditionally, so there is nothing to toggle. `[Copy]` ships
   and is exercised (toast assertion). The panel keeps the library's syntax colours and
   overrides only its Solarized container colour (a class-string merge, not a theme fork).
6. **The detail header has no `[Save]`.** The spec's L281 mock draws `[Edit] [Save]`; the AC
   names only the disabled Edit, and Save belongs to the Phase 3 editor. Saving is p2-07's
   results-pane flow.
7. **Every column's first click sorts ascending** (`sortDescFirst: false`). TanStack's default
   is "auto" — ascending for string cells, **descending** for numbers and booleans — so a first
   click on Level sorted 20→1 and on Mainline showed "checked" first while Status started at
   `extracted`. That direction is decided by the JS type of an accessor the user cannot see;
   measured in the tier-1 spec and pinned. The spec is silent on direction (L254-262).
8. **Column widths are exact, not negotiated.** `table-fixed` plus an inline `{ width }` on each
   `<th>`/`<td>` makes the six px widths the spec's to the pixel, with Quest Name as the flex
   column (`null` width in the shared table). The spec's 40/60/60/40/120/80 are asserted with
   `boundingBox()` in the browser, not only in the unit test.
9. **The Actions column is icon-only** — two 28px buttons — because the spec fixes that column
   at 80px; the Edit action's accessible name carries the quest name (`Edit quest: <name>`) so
   the row is unambiguous, and both buttons stop propagation so they never navigate.
10. **`relativeTime` thresholds are pinned to whole units** and never locale-formatted (a
    machine-dependent string inside a fixed 120px column and inside the specs would be a moving
    target): <45s `just now` (a future mtime is clock skew, not "-3 minutes ago"), <60min
    minutes, <24h hours, <30d days, <365d months (30-day month), else years. The unit changes at
    the whole unit — at 60 minutes the column reads `1 hour ago`, never `60 minutes ago`.
    `modified_at` is `null` when a corpus file vanished before the server stat'ed it → `—`.
11. **`skipped` is not surfaced on the browse page.** `GET /api/quests` reports unreadable corpus
    files, but no AC or spec clause asks the list to render them and p2-07's overwrite check does
    not either; the wire type is mirrored (`QuestListSkipped`) so the contract stays honest.
    **Flagged for the lead:** an unreadable file means the list is silently short (the spec's own
    example says 322) — a one-line notice would be cheap in a later story.
12. **Dependencies** (both `--save-exact`, per the D30/D31 pin discipline):
    `@tanstack/react-table@8.21.3` — the spec's choice (L16) and the React-18-era API line the
    spec text was written against;
    `react-json-view-lite@2.5.0` — the plan's lightness-over-Monaco choice (L64, D25), peers
    `react ^18 || ^19` against our `react ^18.3.1`. `npm ci --dry-run`: "up to date", no
    package.json/lockfile mismatch.
13. **The filter tabs are `role="tab"` buttons without roving arrow-key focus.** The spec calls
    them filter tabs and requires a count badge per tab; the full ARIA tabs keyboard pattern
    (roving tabindex + arrow keys) would model a filter as a tab strip. Recorded as a small,
    deliberate a11y deviation: each button is individually tabbable and the single
    `role="tabpanel"` is referenced by `aria-controls`/`aria-labelledby`.

## corrections the specs forced (tests changed the client, not the reverse)

* `relativeTime`'s minutes branch originally extended to 90 minutes, so a 60-minute-old file
  rendered "60 minutes ago". The unit boundary is now whole (see 10) — found by the browse
  spec's Modified assertions and pinned in the unit test at 59/60/90 minutes.
* TanStack's auto sort direction (see 7) — found by the browse spec's Level sort.
* No existing test was weakened, deleted or skipped to make anything pass; the only edit to an
  existing spec is shell.spec.ts's `/quests` branch, which moved from asserting the *stub*
  ("Arrives in Phase 2") to asserting the real page (search box + Quest Name column) plus one
  real-detail-page assertion on its existing `/quests/DS-ACAD-C01-001` test.

## not claimed here (honest gaps)

* **Tier 2**: the AC's own `(playwright-mcp assertions)` clause and any real-corpus browse pass
  are the lead's. This file is tier 1 only.
* **The 322 rows are a fixture**, not the developer's corpus: the filter counts, "Showing 1-50 of
  322" and page 7's "301-322" are proven against `tests/ui/quests-mocks.ts`, whose numbers are the
  spec's own example. A real-corpus count check is tier 2.
* **768px exactly is untested** (`useIsMobile` = `max-width: 767px`): the specs drive 375 and
  1280, the same two widths p2-06/p2-07 used.
* **`npm ci` was verified with `--dry-run` only.** A full clean install was deliberately not run:
  this host's npm holds install scripts behind an allow-list, so a real `npm ci` would skip
  better-sqlite3's node-gyp rebuild and could leave the workspace's `node_modules` broken for the
  lead's own gate. The runner's `npm ci` (and D41's clone simulation) covers the real check; what
  this story could have broken — lockfile/package.json disagreement — the dry run rules out.
