## ac3 — SUPERSEDED BY MEASUREMENT (`prd_amend`, ledger revision 2)

The original criterion, verbatim: *"CreatureSpellbook rows show a paired name once `decks` is populated."* **Its premise is false**, and both parties measured it independently:

```
my own runs: --select 'Decks/**'                                  -> 599 rows, class {DeckTemplate: 599}, 599 distinct m_name
             the clone's 134 distinct CreatureSpellbook.DeckName values -> matching a DeckTemplate m_name: 0
             --select 'ObjectData/Decks/**'                       -> 3,972 rows, 0 failed; 114 of the 134 match a basename
executor:    15 more match ObjectData/MinionDeck-*.xml; 5 exist nowhere; those items' only name IS the technical value
             a DeckTemplate's only name is its own key in 586 of 599, so a matching row would render 'X (X)'
```
So the family's keys name deck **items**, not `DeckTemplate` rows — **two different namespaces** — and a pair is unreachable for every corpus row. The amendment keeps every checkable part (the 599 rows, the D35 ids, 0 dropped, the mechanism wired with a **synthetic positive control**) and substitutes the reachable claim (technical-only, with the measured reason) for the unreachable one. The **spec's per-family table was the source of the error and the lead corrected it** to a permanent technical-only family; `namePairDistinct` collapses the degenerate `X (X)`, but p6-06's object surfaces were deliberately left unchanged and that shape is recorded as an owner decision.
