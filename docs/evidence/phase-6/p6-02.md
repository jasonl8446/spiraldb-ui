## Bounding the executor's finding about the reference script

It reported that `scripts/wad-census.mjs` reads a 16 MiB window from offset 0, so for any archive smaller than that window it reads payload bytes, and an index larger than 16 MiB would be truncated. The lead measured the blast radius:

```
$ node /tmp/p6/maxindex.mjs <GameData>
largest index: Root.wad = 12054272 B (11.50 MiB), 173088 entries
reference window (wad-census HEADER window) = 16777216 B (16.00 MiB) -> NO real archive exceeds it today (the truncation is LATENT only)
```

**The defect is latent, not active**: the largest real index (Root.wad, 11.50 MiB) is below the window, so no published count is affected. It is recorded rather than fixed here — the script is the reproduction p6-01's numbers cite, and no p6-02 criterion covers it. The new reader has no window and no cap.

## The executor's reported contradictions, and the lead's rulings

1. **`crc32` is not a CRC-32 of anything nameable** — *verified independently by the lead* (above). Recorded in the module docblock; the fixtures therefore carry arbitrary literal `crc32` values rather than implying a convention the corpus lacks.
2. **`wad-census.mjs`'s window/comment** — *confirmed real, blast radius measured as latent only* (above). Recorded, not fixed.
3. **100% v1; v2 is fixture-only; the version guard rejects v3+** — matches the lead's measurement (v1 × 3,589). The guard is documented as evidence-backed. If a future revision ships v3 this is revisited; nothing today is v2 or v3.
4. **8 zero-entry 13-byte archives are accepted** — matches the lead's measurement, and has a fixture arm.
5. **One guard beyond Imcodec** (an entry's data range must fit in the file) — a genuine improvement: an archive truncated *after* a complete index would otherwise parse fully and point every entry past EOF.
6. **Globs match the full stored name, case-sensitively** — the default selection is unaffected (the 6,733 are stored flat); p6-03's `--select` must use `**` for nested paths.
7. **`readWadIndexTree` holds all indexes (316 MB RSS)** — recorded; p6-03 should fold selections in place.
8. **`readWadIndex` needs 2 positional reads per entry (1.1 M syscalls)** — measured 0.84 s for the corpus; no read-ahead window was added, deliberately.

### The one criterion-reading deviation, stated rather than smoothed

**p6-02-ac1's literal subject is `readWadIndex`, which is the per-file primitive.** The 3,589-archive enumeration happens in `readWadIndexTree` (same module, thin recursive walk over the one parser, collecting failures into an `errors` aggregate so a walk can report a parse-error *count* rather than aborting on the first bad file). The lead asked for that function mid-flight precisely because the criterion names the enumeration as the module's job. The lead's ruling: **the criterion is met and is not amended** — the capability and the raw totals are the module's, produced by one call, and the plan's own task text says the reader reads *a* `*.wad` entry index. The symbol difference is recorded here so a verifier sees it; if the final gate insists on the letter, the fix is a rename, not a redesign.
