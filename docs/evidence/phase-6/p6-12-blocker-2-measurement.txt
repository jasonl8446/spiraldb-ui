=== a measured correction to task 6.11's blocker 2 ("Paths are cwd-relative") ===

blocker 2 as written:
  "Paths are cwd-relative (LocalWadCachePath = ./cache, EmbeddedDatabaseDataDirectory =
   ../ImlightEmbeddedDatabase/), which is what makes a workspace copy viable — and means the run
   directory and its parent must both be in the workspace."

--- what the run measured: the two paths do NOT resolve the same way ---

1. LocalWadCachePath = ./cache  ->  the process cwd (the run directory). CONFIRMED cwd-relative:

   (it is a LiteDB FILE, not a directory, and it grows to the size of the wads it caches)

--- what this does and does not change ---
  * the criterion's guarantee still holds: the run directory and its parent are both inside the
    workspace, and NOTHING lands outside it, so no run artifact can leak into git or into a
    sibling tree. Confirmed: find on Imlight's built output shows no file written today.
  * what is wrong is the stated *mechanism* for the embedded database: it is the RavenDB
    child's directory, not the Director's, that '../' is relative to.
  * consequence for .gitignore: the entry that matters is tools/.imlight-run/ (which holds the
    database); the ImlightEmbeddedDatabase/ entry never had a directory to match here.
