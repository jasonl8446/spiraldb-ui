## 2. The measured reality (one file) and THE MATCH FINDING

`TreasureCardInventory/` holds exactly **one** file, `NpcTreasureCards_2019-A.json` (the legacy name; D19's content-keyed index resolves it). Measured 2026-09-27 by the executor on the real fork (md5 `9479cb2f…`, byte-identical to the clone's copy; re-measured by the lead's brief): `TemplateID` **38214**, exactly the schema's two top-level keys, **71** entries of exactly `{SpellName, Price}` (71/71), prices **{100, 150, 200, 250}** (36/13/13/9), **71** distinct names, all 71 ending `" TC"`.

**The finding, measured twice** (`spells`: **18,173** rows, **4,104** distinct names, **0** blank):

| arm | measured |
|---|---|
| the 71 names matching `spells.name` **literally** | **0 / 71** |
| the same 71 with the trailing `" TC"` stripped | **71 / 71** |
| the same 71 with case folded | **0 / 71** |
| `spells.name` containing the uppercase substring `TC` | **0** |
| `spells.name` ending in `" TC"` | **0** |
| `spells` **rows** containing `tc` case-insensitively | **89** (**17** distinct names) |

Two honest corrections to the briefed numbers, both now separate constants so neither can be quoted for the other: the brief's "89 names contain `TC`" is **row-based and case-insensitive** (the class is incidental — `Cat Scratch`, `Hatch`, `Catch of the Day`, `Switcheroo`); the **uppercase** substring count is **0**, and the **distinct** ci-`tc` count is **17** (18,173 rows against 4,104 distinct names).

**The decision (lead, detailed spec wins): match LITERALLY.** `docs/spec-domain-reference.md` L200 says `SpellName` "must match `SpellTemplate.m_name`"; a suffix strip or a fuzzy match is not in the spec. So nothing strips `" TC"`, nothing folds case, nothing consults a second table, and the synced data is never written. **The consequence is honest and non-blocking: on the one real file the UI shows 71 warnings and Save succeeds** — the live transcript records exactly that, and a tier-1 arm proves the *converse* (`Fire Shield` matches; `Fire Shield TC` does not) so the literal reading is testable rather than incidental.

**Owner decision, exposed rather than resolved by behaviour**: if `" TC"` is a genuine part of this family's contract (the corpus supports it 71/71), the change is one line in `validateTreasureCardInventory` plus the corpus constants — recorded, not taken. The suffix-stripped 71/71 number is asserted in the unit sweep as a **finding about the data**, never as behaviour.

## 3. Which side carries which claim (stated, not blurred)

- **The shared engine carries the rule**: `shared/simpleObjects/treasureCardInventory.ts` (pure; no React/json5/SQLite/`server/` import), with the reference set **injected** — so either half of the app can run one implementation (the p4-02 precedent).
- **The client carries the claim a user sees**: `TreasureCardInventoryDetailPage` injects the synced names (`useSpellNames` → the already-cached `GET /api/names/spells` query) and the form renders one inline warning per row + a form-level summary. `L547`'s Save rule is about **errors**; this family emits none.
- **The server carries no claim and rejects nothing for a warning**: this family has no blocking rule, so its `treasurecardinventory` row is mounted **without** a `validate` (the seam DropTable alone takes). A validator that could only ever return would be copy without a surface. **Proven, not asserted**: in-process (`tests/unit/treasure-card-inventory-model.test.ts` — a document whose every name fails the match saves into a throwaway repo) and **live** (`HTTP 200` for the real 71-warning file, `warnings: []` in the response body).
- **The converse arm is pinned too** (so this story did not accidentally make everything non-blocking): the unit test asserts the family emits **no** `severity: 'error'` message for any document, and that the shared `fieldHasError` still returns `true` for an error — the gate a future blocking rule would land on. **No `Price` rule was invented**: the spec prints no bound for `Price` (not even a lower one), so a negative or fractional price is not flagged.
- **D65(c) when the table is absent**: an empty/unloaded `spells` table means "this side cannot check" — the engine produces nothing and reports `referenceUsed: false`, and the form says the names were not checked instead of showing a clean pass (tier-1 arm 9).

## 5. Reuse decisions (generalise, do not fork)

- **The object-list reader/builder is this family's own**, beside the shared list primitives rather than inside them: `TreasureCards` is an array of **objects**, and the existing primitives are for arrays of **ids** (`readNumberList`/`readStringList`, `addToList`, `removeAtIndex`). The style is theirs; the module header of `shared/simpleObjects/model.ts` was corrected (it had claimed 4.7's list was "numeric again" — it is not, measured 71/71).
- **No new add control**: `RawIdAddControl` appends an id to an **id list** and `ObjectIdMultiSelect` renders chips — neither is an object repeater. The Add box (a text box + `Add card`) is named **once**, inline, and reuses the shared `textIdFromRaw` guard (a blank is refused; a name is stored verbatim, so an unlisted name — the case the warning is for — can be typed directly). The element key type `'treasure-card-list'` was added to `SimpleFieldKind` (the vocabulary's own way of growing).
- **One `Data`-not-copy rule**: the `Price 0` hint, the new row's price (the corpus's most frequent, 100), the entry key order and every measured number live in the shared module; the form and the tests read them.
- **The warning sentence has one reader**, so it lives in `client/src/lib/treasure-card-validation.ts` (with the path key still from the shared `formatDocPath`), unlike p4-02's shared copy table — which exists because a **server 400 map** must word it identically. Recorded so the difference is a decision, not an accident.
