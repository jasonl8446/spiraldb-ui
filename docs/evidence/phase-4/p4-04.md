## 2. The measured reality (the family has no corpus at all)

`NpcDropTable/` **does not exist** → **0** files, **0** `entry_status` rows. Everything here is therefore schema-derived rather than file-derived (`{TemplateID, DropTableNames}`, the array holding **names**), which is why the unit test asserts the **absence** explicitly: a future round that creates the directory must update the constant rather than silently invalidate it.

The name source is real and was measured: `drop_tables` **317 rows / 317 distinct / 0 blank**, and the **DropTables corpus is also 317 distinct names with zero missing in either direction** — a bijection, re-derived independently by the lead, which is what lets the picker reach the whole real vocabulary. The spec's own example `WC-UNICORN-BONUS-001` is **absent** from those 317 (0 names contain `BONUS`), so it is a real "unknown name" case: storable, shown raw, and typeable back through the raw-name box — the miss-safe path the tier-1 spec exercises.

## 5. Reuse decision (D71(i) honoured)

The story needed a **text-keyed** multi-select and the codebase already had a numeric-keyed one. Rather than write a second, the executor **generalised the existing pair**: `ObjectIdMultiSelect` and `RawIdAddControl` now take `idKind: 'number' | 'text'`, and the shared list primitives (`containsId`/`addToList`/`removeAtIndex`/`moveInList`/`replaceListEdit`) were made generic in `T` so there is no per-kind fork. Only two things differ between the arms — the parse and the search placeholder. The numeric arm is **regression-checked by the lead's own spec** (the p4-03 behaviours still hold exactly).
