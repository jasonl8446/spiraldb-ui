## 2. AC#13 — the breakpoint, the arms, and what carries each claim

**The breakpoint, stated once.** The criterion says ≤768px; the app's own switch is
`useIsMobile`'s `(max-width: 767px)` — Tailwind's `md` boundary, which is what
docs/spec-ui-design.md L234/L270/L340 mean by "below md" / "Table becomes card list" / the mobile
overlay. So the mobile surface is asserted at **375** (a phone) and at **767** (the widest
viewport the app calls mobile — the strongest reading of "≤768"), and the **converse is asserted
at 768**, where desktop mounts. At exactly 768px desktop wins; that one-pixel gap between the
criterion's wording and the implementation is pinned by the boundary arm rather than papered over
(§7).

## 5. The falsification pass (D67(d)) — the spec is load-bearing

Four deliberate breaks, each restored afterwards; each run named its own config (§6). The three
**broken-and-restored files are byte-identical** (`md5sum` before/after):

| break | how | result |
|---|---|---|
| **1a** | `ObjectListPage`: render the desktop table at every width (`isMobile ?` → `false ?`) | **7 failed / 14 passed** — exactly the 7 list arms; the failure is the card-count assertion (`Expected: 3, Received: 0`), i.e. the card-DOM claim carries itself |
| **1b** | `ObjectListPage`: mount **both** surfaces at every width (the break 1a run exposed a vacuity — see below) | **7 failed / 14 passed** — the same 7 arms, but failing on `getByRole('table') Expected: 0, Received: 1`: the **table-absence** half is real, not a tautology |
| **2** | `QuestJsonPanel`: the mobile dialog no longer covers the viewport (`h-full w-full` → `h-1/2 w-1/2`) | **8 failed / 13 passed** — the 7 keyed detail arms + the registry arm, failing on the polled box (`{"height":400,"width":188,"x":0}` vs `{375,800,0}`): the overlay claim is a **geometry** assertion, not a visibility one |
| **3** | `ObjectIdMultiSelect`: value-based removal instead of index-addressed | **1 failed / 20 passed** — exactly the duplicate arm; `['Spiral Wand']` where `['Black Mantle','Spiral Wand']` was required, i.e. the surviving duplicate was collapsed |

**The pass changed the spec.** Break 1a failed on the card assertion while the `table` count-0
line **passed** — because `toHaveCount(0)` is satisfied by the page's loading state, so that line
was vacuous when placed first. The spec now asserts the (retrying) card count **first** and the
table's absence **on the loaded page**; break **1b** exists to prove that line is load-bearing.
The three-screen-resolution claims the AC names were therefore verified by *trying to break them*,
and one of them had to be repaired to be honest.
