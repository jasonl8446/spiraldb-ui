## 1. The criteria

| AC | How it is satisfied |
|---|---|
| **AC1 — NpcInventory**: NPC `FriendlyNameDropdown` + **searchable multi-select over `items` names rendered as removable chips**; renders, edits, saves | **This story closed a gap rather than rewriting.** p4-01's form already had the NPC dropdown, removable chips and the pipeline mount — but its chips rendered **raw numeric ids** and the only add path was a numeric box: **no access to the 79,835 item names at all**. Added: `ObjectIdMultiSelect.tsx` (the **one** chips component, popover + cmdk over `useNames('items')`, searching names *and* ids) with **index-addressed** removal, and `RawIdAddControl.tsx` (the raw-id add box named once) — kept deliberately, because **42 of 3,205** corpus ids have no synced name. Chips show the synced **name**, or the raw id when unresolved |
| **AC2 — NpcSpellInventory**: NPC dropdown + a spells repeater `{ TemplateID spell dropdown, RequiredSpellID with an explicit "none (0)" option, Level number }` | `NpcSpellInventoryForm.tsx` renders the repeater. `none (0)` is the shared dropdown's **clear** option (`emptyLabel="none (0)"`, the one shared change) with `value={null}` when the value is the sentinel, so **no lookup for spell `0` is ever issued** and the stored value stays `0`. The Level box is `type="number"` with **no `min`**, and an emptied box writes `0` rather than deleting the key — because the 3-key entry shape is 560/560 in the corpus. Adding a row is a **pick-to-append** dropdown (no placeholder row), because `TemplateID === 0` occurs **zero** times in the 560 real entries |
| **AC3 — CreatureSpellbook**: `DeckName` key + a **reorderable** `SpellTemplateIds` list with spell dropdowns | `CreatureSpellbookForm.tsx` renders `DeckName` plus the reorderable list, with `Move up`/`Move down` over `moveInList` and one whole-array replacement. `DeckName` empties through the shared present-aware rule (emptying deletes the key and the server then refuses the POST with "no usable DeckName") |

Routes for `/npc-spell-inventories[/:id]` and `/creature-spellbooks[/:name]` were wired in `App.tsx` (they were Phase-4 stubs), so all three families now go through `ObjectDetailLayout`/`ObjectDetailPage` into the **existing** generic save pipeline.

## 2. Measured corpus reality this story rests on

| Type | Files | Keys (exactly) | Payload |
|---|---|---|---|
| NpcInventory | **215** | `TemplateID`, `Inventory` | 3,785 values, 3,205 distinct, **1 empty array**, 3,163 resolve / **42 miss** |
| NpcSpellInventory | **77** | `TemplateID`, `Spells` | **560** entries, each exactly `{TemplateID, RequiredSpellID, Level}`; **`RequiredSpellID === 0` in 239**; `Level` **0–420** |
| CreatureSpellbook | **134** | `DeckName`, `SpellTemplateIds` | 1,267 values, 369 distinct, **9 empty arrays**, 368 resolve / **1 miss** (`213674121`) |

Everything is a JSON **number** in all three types (0 non-numbers across 6,712 values), so the string↔number trap that bit DropTable's `ItemId`s does not appear inside these documents — only at the control boundary, where one helper (`numberIdFromRaw`, delegating to the p4-01 `ULong`) converts.

**A fact the lead did not measure and the executor's sweep found: 14 NpcInventory and 4 CreatureSpellbook files carry a DUPLICATE value inside their single list.** That is why every list edit is **index-addressed** (`removeAtIndex`, `moveInList`) rather than value-addressed — a value-based removal would silently collapse a real duplicate. It is asserted both ways (§5).

## 6. Falsification (D67(d)) — and it found a real gap in the spec itself

Three deliberate breaks, one per AC: the chip label forced to the raw id; the `none (0)` **option** relabelled `'None'`; and both `Move up`/`Move down` made no-ops. Result: **7 failed / 7 passed**, then all files restored with **md5-verified byte equality**. The exercise exposed that AC2's first test asserted `none (0)` on the **trigger**, which still passes when the option is mislabelled (the trigger shows the placeholder) — so the test now asserts the **option** by name, and the story's spec is 14/14 again. That is the falsification method earning its place rather than decorating the record.

## 7. Flagged, and the limits

- **AC3's reorder is `Move up`/`Move down` buttons, not a pointer drag.** The criterion says "reorderable", and the buttons are keyboard-exact with no sensor timing window (D60(i) records the dnd-kit timing flake that motivated the choice) and no new code path. A pointer drag would layer onto the same `moveInList`/`replaceListEdit` pair if the owner wants it.
- **No `min`/`max` on Level at all** (the spec prints none; the corpus spans 0–420), and a cleared Level box writes `0` rather than deleting the key — a deliberate departure from the top-level scalar rule D59(c), documented in `npcSpellInventory.ts`, because the 3-key entry shape is 560/560.
- **The 42 + 1 misses stay raw everywhere** and no lookup is issued for `RequiredSpellID: 0`; the tier-1 spec pins this with `recorded.spellLookups` never containing `'0'` and `recorded.itemLookups` for the fallback path.
- **Two committed specs were updated as phase transitions** (not weakened): p4-01's `object-list.spec.ts` now **mocks the `items` table** (previously it would have hit the real 79,835-row table) and asserts the new chips contract including a deliberately absent id (`160999`) for the raw-id chip; and `shell.spec.ts`'s two "Arrives in Phase 4" stub branches became real-list branches.
- **The extraction load-flake recurred once more** (`extraction.spec.ts`: a sonner toast intercepted `Save All`). It passes 22/22 in isolation and in both later full runs, in a page this story does not touch — the third sighting of the family D69(h) recorded, still owed to gate-4.
- **D17 hygiene verified this round** (after the lead polluted the clone in round 47): the real fork is at `c55ccab` with 0 dirty, the clone at `18dc924` with 0 dirty, **no listeners** on 5173/3001/3217–3220 and **no `tsx server/src/index` processes** left.
