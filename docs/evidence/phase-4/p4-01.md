**Every legacy prefix differs from the spec's create-prefix**, which is why a filename-derived lookup would have broken on 100% of existing files and why D19's index is the resolver. The **unprefixed NpcSpellInventory file** is indexed and never renamed (D19's case). **`NpcDropTable/` does not exist**, so reads had to tolerate it. **GlobalRegistry has no status rows** — and the lead's original claim that ZoneTransfer had none was WRONG: measured later, `zone_transfer` has **1205** rows (D74). The list's status join still had to tolerate absent rows, which the GlobalRegistry case covers.

**The one count that differs from a raw file count, measured rather than assumed**: `/api/zone-transfers` returns **1205** rows for **1207** files, because the corpus has **1205 distinct `ZoneName` keys** — `WizardCity/Tutorial_Exterior` and `WizardCity/Tutorial_Interior` each appear twice, and **0 files are unparseable**. A keyed list is right to collapse them; the duplicate pairs are reported in the index's own stats (its full probe: scanned 2587 / indexed 2587 / skipped 0 / failed 0, `missingDirectories: ["NpcDropTable"]`, plus 7 duplicate QuestMetadata names).

## 4. Two things the story decided rather than guessed (D69)

- **Audit fields are NOT stamped.** `audit: 'embedded'` in the type table is **declarative only**. Measured: **316 of 317 DropTables** carry `CreatedAt`/`CreatedBy` + `ModifiedAt`/`ModifiedBy`, while the **other six families carry none**. A generic writer refreshing `ModifiedAt` would therefore introduce an invisible second writer across ~2,000 corpus files and break task 4.2's acceptance criterion that a save's `git diff` shows *only* the edited field. The config records where audit lives for the types that have it, and the keys ride through the D5 merge untouched.
- **A render-loop defect the tier-1 spec caught, and it was a real one**: `ObjectTable`'s `extraColumns = []` default created a fresh array on every render, so TanStack Table saw new column definitions each time and the page **froze** — the spec's first `Next` click never completed (60 s timeout). Fixed with a module-level empty array plus memoised `data`/`href`/`activateRow`; the spec now finishes in 1.5 s. The object list was unusable before the fix, which is exactly why the story's overriding criterion demanded a tier-1 spec.

## 5. Flagged, not hidden

- **`tests/ui/extraction.spec.ts` is load-flaky and this diff does not touch it.** Across four full UI runs: three green (177), and one failing a *different* extraction results-phase assertion each time (`:774`, then `:807`) at the 10 s expect timeout; both pass in isolation (7.2 s and 1.5 s). The extraction page/components/hooks/lib import none of the files this story changed (checked by grep). Under this host's peak-hour load a 10 s expect is marginal, so this is recorded as a **pre-existing load-flake for gate-4 to weigh** — a gateway that fails intermittently on load, not on behaviour.
- **Wire shapes are spec-silent and therefore agent-chosen**, recorded as binding for the rest of Phase 4: list body `{objects, summary, skipped, missing_directory, duplicate_keys}`; POST body `{object, notes?, key?}` and response `{key, file_type, object_type, outcome, action, commit, branch, commit_message, file, status, status_created, warnings}`; status codes 400 (bad body / unset `spiraldb_path`), 404 (unknown key), 409 (dirty tree), 500. A create records the history note `Created via UI`. An unkeyed GlobalRegistry save warns in `warnings` that other files remain — task 4.9's consolidate-and-replace owns removing them.
- **Only `/npc-inventories` is wired end to end by design**; the other seven families keep their stubs until their own tasks.
- No POST was issued against the clone in the live pass (D66), and no rig was left running: the lead's own D1 rig on 3219 and the executor's rig were both killed by PID, and a **stale listener from an earlier round was found holding 3216** and killed.

## 6. What this story did not prove

- The eight list **counts** are proven live; the eight **forms** are not — only NpcInventory has one so far (by design).
- No save was executed against the clone in the live pass: the POST paths are proven by unit tests over a fixture tree (create/bootstrap, original-path update, the exact commit messages, the status upsert) and by the earlier phases' clone-based save tests, not by a live POST here.
- `audit: 'embedded'` is deliberately inert (§4), so the audit-key *preservation* claim rests on the D5 merge behaviour asserted in Phase 3, not on a fresh write.
- The mobile (≤768px) pass for the new list/detail pages is task 4.10's, not this story's.
- No pixel inspection (no screenshots were needed for this scaffolding story).
