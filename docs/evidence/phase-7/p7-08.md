## What was built

- **Server (D141).** `POST /api/quests` takes `accepted_suggestions: number[]`: parsed (positive integer ids,
  de-duplicated) and checked (each exists, is pending, is this quest's) **before** the pipeline runs (400 naming the
  id), then flipped in one transaction **after** the commit. `acceptSuggestions` is split into
  `assertAcceptableSuggestions` (pre-write) plus the flip (post-commit, re-checked).
- **Server (D142/D137).** `POST /api/quests/scaffold` takes optional `quest`, `catalog_id` and `accepted_suggestions`.
  `quest` is validated as a save is (name = `quest_name`, shared schema, blocking rules) and written in the
  scaffold's single commit. A `catalog_id` whose `quest_ids` row is unlinked makes the save **name** the draft: a
  duplicate (a `quests` row or a quest file) is 409, an unsafe path is 400 (the scaffold's own guard), and a refusal
  writes nothing. On success, one transaction after the commit creates the `quests` row, links the id, names the id's
  suggestions and flips the accepted ids. New read: `GET /api/quests/:name/scaffold`, the unwritten skeleton.
- **Client.** `/drafts` (QUESTS → Drafts) with the ranked queue, the Named / Has file / Source selects, the name
  pair, and the zero-evidence toggle with its count. Two file-less editor routes, `/drafts/quest/:questName` and
  `/drafts/id/:questId`. Inline suggestions sit at the top of the tab holding each field, as
  `Suggested: … · source · confidence [Accept] [Reject]`, with "Accept all from <source>" above the form. Accept is one
  `DocEdit` through the document state's own `editAll` (D58). Reject is immediate. Save carries the applied ids. An
  unnamed draft's Save opens the D137 name dialog.
- **Harness.** `npm run imlight:boot -- prove-count --save-cmd <command>` runs any write between the two boots in
  place of p6-09's scaffold. Snapshot, boots, count proof and restore are unchanged.
