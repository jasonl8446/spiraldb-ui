## What changed

- `tools/PacketReaderCli/ReaderRepairs.cs` (new) holds the post-pass repairs. It runs after QuestBuilder and the D46
  level repair, and before the 7.3 observed fields. Nothing joins by position.
  - **Goal join + ACHIEVERANK** (`JoinGoals`). The pass builds the GoalID → goal map (D150's owner rule). Take a
    later `GoalID` whose `GoalNameID` is already owned: if its packet is `GOAL_TYPE_ACHIEVERANK` with an empty
    `GoalTitle`, it is a distinct goal. QuestBuilder skipped it as a duplicate, so it is built from its packet with
    QuestBuilder's field mapping and inserted in capture order. Then every packet goal is named `{n}_{GoalTitle}` by
    its position. The corpus names ("Trigger Storm", …) appear on no packet (`MSG_SENDGOAL` in `QuestMessages.xml`
    has no goal-name field), so `{n}_` is the only name the packet data gives.
  - **Quest-level Prep/Completion by GoalID** (`RepairDialogs`). QuestBuilder takes the first `QuestInfo` packet of
    the offer's MobileID and the first `Completion` packet of the QuestID, whatever their GoalID. The game server
    sends a goal's Completion dialog with the quest id (Imlight `QuestService.cs:1108,1134-1140`). When
    QuestBuilder's pick has a non-zero GoalID, the pass replaces it with the first matching GoalID-0 packet, or
    removes it when there is none. Each such change prints one `reader-repair` line.
  - **Goal dialogs by GoalID.** QuestBuilder maps a GoalID only for goals it added from a packet. The pass attaches
    the dialogs of the other goals it joined, using QuestBuilder's tag rule and replace-by-tag semantics. Those goals
    are compilation goals re-sent by `MSG_SENDGOAL` and recovered goals.
  - **More dialog.** A quest-level `Underway` `MSG_ACTORDIALOG` (QuestID, GoalID 0) becomes an `Underway` block.
    `MSG_ENCOUNTERDIALOG` becomes a block on its GoalID's goal, or on the quest for GoalID 0. An encounter dialog
    never replaces a block of the same tag: an identical one is skipped, and a different one is reported.
    `MSG_ACTORDIALOG.IsYesNo` (when 1) and `.DefaultDialogAnimation` (when non-empty) are read and reported as
    `observed-field`. The dialog block schema (`ActorDialogBlockSchema`: tag, entries, madlibs, events, two no-aggro
    flags) has no field for either. `m_defaultDialogAnimation` exists only on `QuestTemplate`, where it is an Imcodec
    `std::string`, the shared schema models it as an opaque object, and it is null in 322/322 quests. Nothing shows
    that a per-dialog packet value is the quest's.
- `tools/PacketReaderCli/Program.cs` handles the **unlisted goal type**. When QuestBuilder throws
  `NotSupportedException("Unsupported goal type: X")`, the CLI re-reads a scratch copy of the capture without every
  `MSG_SENDGOAL` of type X and every message carrying their GoalIDs, prints one `goal-excluded` line per goal, and
  repeats. The post-passes read that same filtered copy. A compilation goal of an unlisted type (inside
  `GoalData`) is not excluded, and that throw still fails the run.
- `tools/PacketReaderCli/ObservedFields.cs` now uses the shared GoalID join, so recovered goals get their values.
  Its helpers are `internal` for reuse.
- `tools/FixtureGen` changes:
  - `--inject` gains dialog steps (`MSG_ACTORDIALOG`, `MSG_ENCOUNTERDIALOG`, `goal` optional), the
    `{"$blob":"ActorDialog","entries":[…]}` blob (mask 16, decode-checked) and `goalDialogQuestId`.
  - A planted `MSG_SENDGOAL` field (for example `GoalType`) replaces the engine's, as before.
  - Without `--inject`, three refusals are lifted, because the wrapper now rebuilds those shapes. A compilation goal
    that carries dialogs is re-sent by `MSG_SENDGOAL` and its dialogs follow it. A goal dialog tagged `QuestInfo` is
    no longer refused. A quest with no goals is emitted. A scratch probe build showed 3 of the 11 no-goal quests
    reconstructing with `m_goals []` before the lift.
- `tools/CaptureCensus/Program.cs`: `MSG_ACTORDIALOG.IsYesNo`/`DefaultDialogAnimation` and
  `MSG_ENCOUNTERDIALOG.QuestID/GoalID/CompletionType/ActorDialog` are now consumed. The table's line citations are
  refreshed.
- `scripts/audit-corpus-roundtrip.mjs` drops the three lifted refusal keys and lists every refused quest with its
  class.
