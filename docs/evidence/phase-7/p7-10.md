### Changed locators (complete raw listing: `git diff tests/ui tests/unit` → docs/evidence/phase-7/p7-10-locators.diff, 1649 lines; line numbers below are the new file's hunk starts)

Rules applied, and why none loosens an assertion:
- **R1 label → pair, `exact` kept.** `getByLabel('m_X', { exact: true })` and `getByRole(..., { name: 'm_X', exact: true })` → the glossary pair (`'Quest level (m_questLevel)'`), still exact; the pair contains the old key, so the element matched is the same one. Friendly-only exact labels likewise (`'NOT'` → `'NOT (m_applyNOT)'`, `'Type'` → `'Type ($type)'`, `'School'`, `'Entry'`, `'Target Type'`, `'School Name'`, `'Quest Registry'`, `'Display Name'`).
- **R2 address in aria → `data-path`.** A helper that matched `name: \`${title} ${address}\`` exactly now matches `[data-path="<address>"]` (exact attribute equality, so `m_requirements` still cannot match `m_requirements[1]`) **and** `[aria-label^="<title pair> "]` (the class/ordinal/verb the name starts with). Both halves of the old exact name are still pinned: the address exactly, the title exactly.
- **R3 exact names with words.** Where the address is a literal, the exact accessible name is written out in words: `'Add Condition to Requirements'`, `'Delete Start results › Results 1'`, `'Quest (m_questName) Items 1 › Requirements 1'`, `'Spells for Template ID (m_templateID) Start results › Results 1'`, `'Requirements for Dialog list › Dialog blocks 1 › Dialog entries 1'`.
- **R4 option lists / titles → pairs, same equality.** `toEqual([...])`/`toContain(...)` over option texts and unit `toBe(...)` over titles pin the pair string (`'Not an activity (ACTIVITY_NotActivity)'`, the 4 requirement and 14 result pairs). `not.toContain('ResActorDialog')` → `not.toContain('Actor dialog result (ResActorDialog)')` (the old bare string can no longer appear in any option, so keeping it would have become vacuous; the pair is what an offered ResActorDialog would render).
- **R5 badge / summary.** Goal class badge: `getByText('WaypointGoalTemplate', {exact})` + class check → `typeBadge()` = the element around `[data-term="WaypointGoalTemplate"]`, `toHaveText` the **whole** pair (stricter than the old visibility) and the same colour-class check. Summary regexes take the pair label (`summary('Zone (m_zoneTag)', …)`), and the bounty-type value is now asserted as its pair `Kill mobs (BT_MOB_KILL)`. `cardOrder()` reads `article header > span.font-mono` (the name span) because label technical halves are now mono too — same elements as before, no extra ones.
- **R6 evidence target.** `toContainText('m_goals[0].m_goalText')` → `expectTarget()`: `[data-path]` **equals** the path (was a substring) and the text contains `Insert into: Goal text (m_goalText) in Goals 1`. Unit: `toContain('→ m_goals[2].m_goalText')` → a regex over the whole rendered `→ <span data-path=…><span data-term=…>Goal text (…m_goalText…)</span> in Goals 3</span>`.
- **R7 disambiguation.** quests-detail `getByText('m_dialogList', {exact})` resolved to 2 elements once the goal-level heading also carried the key → `getByRole('heading', { name: 'Dialog list (m_dialogList)', exact: true })` (role + exact name: stricter).
