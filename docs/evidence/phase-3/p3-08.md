## 3. Measured corpus facts this story rests on

- **The real shape is three levels.** `m_dialogList` is `{$type: …ActorDialogList…, m_dialogs: […]}`,
  present in **322/322 quests** and in **445 goals** (767 lists; **327 goals carry `m_dialogList: null`**).
  A tag group is a plain object with a **uniform 6-key order** (`m_dialogTag, m_dialogEntries,
  m_madlibs, m_dialogEvents, m_noAggroWhileDialogIsUp, m_noAggroNoDelay`) — **739 groups**, of which
  **0 have an empty `m_dialogEntries`** — and **43 lists have an empty `m_dialogs` array**
  (**7 quest-level + 36 goal-level**, a split the lead re-measured after doubting the UI's own copy;
  the copy is right).
- **1706 `NPCDialogEntry` nodes, 66 distinct fields, all typed** `…NPCDialogEntry…`, in **three key
  shapes**: 1698 full, **6 truncated at 45 keys** (missing the audio/animation/UI tail), and
  **2 headless at 60 keys** (missing the first six identity fields, `m_personaName … m_invisible`).
  The two sparse shapes must never be padded — this story's primary risk.
- Tags: **`"Completion"` 418, `"Prep"` 316, `""` 5** — an empty tag is a real value, and
  `(empty tag)` / `(no tag key)` are two different honest labels (0 groups lack the key).
- `m_madlibs` is `{m_madlibBlock, m_index}` in 705 groups and **null in 34**; its children are typed
  `MadlibArgT_ByteString`. `m_dialogEvents` is **null in 739/739**; entry `m_action` is **`""` in
  1706/1706**; entry `m_requirements` is **null in 1706/1706** (so the plan's "`m_requirements` → the
  3.6 tree" is implemented and mounted but **fixture-only here**).
- **The three "array" fields are arrays of ENCODED STRINGS**, not objects:
  `m_npcStandInList` = instance names, `m_dialogAnimationList` = `"0|126322|Gen_Dial_01|5"`,
  `m_dialogTurningList` = `"0|38119|50|1"`, each `[]` when unused; all **1144** real elements
  round-trip byte-exactly through the model's text helper.
- **References**: `m_actorTemplateID` → npcs **115/115**; `m_walkAwayNpcTemplateID` → npcs
  **30/30 nonzero** (`0` = none); `m_dialog` → the string table (`string_table.key`, 216,991 rows)
  **1099/1105** with 6 misses; `m_cameraZoneName` → zones **73/87** (interior variants miss);
  `m_personaName` has 149 distinct values and resolves in **no** table.
- `m_cameraHidePlayers`' measured domain is **0 (667), 1 (104), 2 (934), 3 (1)** — four values, so
  the spec's "0=no, 2=yes" is incomplete; an unlisted value must stay a number and stay selected.
- `m_maxTimeSeconds` **-1 = unlimited**; `m_nameSTKey` is `NPCFormats_First_Last` 1298 /
  `NPCFormats_First_Only` 292 / null 105 / `""` 9.
- **Correction to the lead's own brief, found by the executor**: the second sparse shape omits the
  **first six** keys (`m_personaName … m_invisible`, 66−6 = 60), **not thirteen** — `m_requirements`
  onwards are present. The lead's independent spec asserted the right thing (`no m_personaName`);
  the prose was wrong and is corrected here.

## 7. Decision D64 (recorded in `docs/plan-overview.md`)

- **The three-level shape and the group's 6-key order are pinned**, with `m_dialogList` at two homes
  and null in 327 goals; **43 empty lists (7 quest + 36 goal)** and **0/739 empty entry arrays** —
  which is why a **new tag group starts with one default entry** (the lead's decision, distinct from
  the empty-array default the executor first wrote, consistent with p3-06's recorded rule).
- **The 5-accordion → 7-group mapping is fixed and documented**: Basic ← Basic (open);
  Camera ← Camera; Sound ← Audio; Animation ← Animation & NPC; Advanced ← Duration & Timing +
  Walk-Away + UI Controls. `m_soundFile` stays in Basic (the domain reference's own grouping) while
  the Audio group's `m_soundEffectFile`/`m_musicFile` go to Sound.
- **The three sparse shapes must not be padded**, and 8 real entries carry two of them.
- **`m_dialogTag` is the one text control whose empty state writes `""` instead of deleting the
  key** (5 measured empty tags; deleting would break the uniform 6-key group order 739/739). Every
  other text/number control follows D59(c).
- **`m_cameraHidePlayers` is a numeric select** over the four measured values, and an unlisted value
  stays a **number**, selected — the spec's two-value description is incomplete.
- **Duplicate is a verbatim deep copy** placed after the original, so duplicating a sparse or legacy
  entry yields a sparse or legacy entry.
- **`m_defaultDialogAnimation` is modelled, labelled synthetic and read-only** (an opaque object),
  never written into a new entry — so a new entry is exactly the corpus's 66 keys.
- **The raw-fields disclosure is a legacy affordance**: the corpus has 0 unmodelled entry keys, so
  AC2 is fixture-proven and the live pass shows the honest empty state.
- Coverage honesty: `m_requirements`, `m_action` (as a non-empty value) and group `m_dialogEvents`
  are corpus-empty, so their editing is fixture-only; `m_madlibs` and `m_dialogEvents` are surfaced
  read-only in the group-fields disclosure rather than edited; no tag delete and no entry reorder
  (the spec's dialog section has neither); the optional path picker was skipped as the plan allows.
