**Design notes from the spec itself** (its own recorded choices): the read-back is the panel's
`[Copy]` affordance (`JSON.stringify(liveDoc, null, 2)`) rather than the rendered tree text, because
`QuestJsonPanel` renders react-json-view-lite with `collapseAllNested` — nested nodes start
collapsed, so a field inside `m_goals` is not in the tree; the clipboard is wiped and polled before
every read and `openJson` is visibility-checked so a second read cannot toggle the panel shut;
`exact: true` is used where labels could collide (the `m_proximityTag`/`m_goalNameID` substring
hazard p3-04/p3-09 hit); Save is scoped to `<main>`; one compact clean fixture factory is shared by
the four independent tests.

## 5. Independent verification (lead-authored)

`p3-11-lead-verify.txt`:

- **Falsification, because a spec that cannot fail is worthless**: I made the JSON panel render the
  **stale baseline** instead of the live document (`quest={document.doc}` → `quest={document.baseline}`
  in `QuestDetailPage`). **All four chains failed.** The probe was reverted with `git checkout --`
  and the file's md5 matches HEAD on both sides before the final green run — so each chain genuinely
  reads the live document through the panel, and none is a tautology.
- **A flake my own first gate run exposed, and its honest fix**: it failed the committed p2-07
  assertion `expect(box?.width).toBe(400)` once, under load, while passing twice in isolation. The
  diagnosis is that the panel **slides in**, so an immediate `boundingBox()` can land mid-transition —
  a latent race that the Wrap container p3-10 added made wide enough to lose. The assertion is
  **right** (spec L326 says 400px), so it was not relaxed: it is now polled with the repo's
  established `expect.poll` pattern. Three isolated runs pass and the full suite passes with the
  flake gone.

## 6. Decision D67 (recorded in `docs/plan-overview.md`)

- **The AC#13 chain suite is the phase's cross-cutting proof**, and it asserts the AC's own read-back
  surface (the panel's `[Copy]` serialization of the live document) rather than the rendered tree,
  because the tree renders nested nodes collapsed — with the top-level `m_questName` asserted in the
  tree so liveness itself is still covered.
- **The four chains are independent tests**, sharing one clean fixture, so a failure in one cannot
  mask another.
- **A measurement that races a CSS transition is a flake, not a tolerance**: the 400px assertion was
  made deterministic by polling, not by loosening the expected value — the distinction matters
  because relaxing it would have quietly retired the p2-07 contract.
- **`npm run test:ui` in CI is the mechanism** that makes "committed spec passes headless in CI" true
  by construction (`.github/workflows/ci.yml`): nothing in this story needed a CI change.

## 7. What this story did **not** prove

- **CI itself has not run this spec yet**: "passes headless in CI" is structural (the workflow
  collects `tests/ui/*`) plus local evidence (170 passed headless); the actual green CI run arrives
  with the phase PR at **gate-3**, and D66(g)'s shared-clone caveat about the *unit* suite still
  stands there.
- No pixel inspection (no screenshot was needed for a test-only story).
- The chains cover the four AC#13 interactions; they do not re-verify the other five editors'
  field-level behaviour, which their own specs own.
- The flake fix addresses the transition race in that one assertion; if other p2-07 measurements race
  the same transition they would need the same treatment (none failed in the runs above).
