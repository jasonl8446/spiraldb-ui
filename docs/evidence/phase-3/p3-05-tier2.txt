the validation details listed `Entry 3 references unknown goal(s): 4_…` / `Entry 4 references …`.

so goals 5–7 remained reachable from `m_startGoals`, and the only findings were

single app chunk grew 574,044 B → 868,865 B raw and **+95.1 kB gzip**, every byte of it on the
entry path of every route. The lead contained it behind `React.lazy` + `Suspense` in the panel
map, and measured the result on the real stack by reading `performance.getEntriesByType('resource')`:

Post-containment build: entry `index-BujkeyMJ.js` 575.86 kB / **gzip 177.23 kB** (pre-story:

plus a 15.87 kB CSS chunk. Without the containment every route in the app would have paid the
97.8 kB gzip.

## What this pass did **not** prove

- No image input in this model, so the three screenshots' **pixels** were not inspected; every
  claim above is a DOM, ARIA-name, class-list or clipboard read.
- Dragging a **new edge between two handles** (`onConnect`) was wired and unit-tested but not
  driven in the browser: creating a valid new connection changes which goals are reachable, and
  the AC does not name it. Recorded rather than claimed.
- The 768px/mobile layout of this tab was not re-checked (the editor renders inside the desktop
  tab panel p2-07/p3-03 already cover).
- No Save was pressed, so "appears in **saved** `m_goalLogic`" is proven to the live document and
  the JSON panel, not to disk — the save pipeline's formatting-only diff contract is D49's and is
  unchanged by this story.
- The dashed OR edge could not be exercised with corpus data (there is none); it is tier-1 only.
