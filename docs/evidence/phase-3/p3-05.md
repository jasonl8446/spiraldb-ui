## 3. Measured corpus facts this story rests on

The whole `m_goalLogic` surface was surveyed before implementation and re-derived independently in
§5. 322 quests hold **742 entries** across **307 quests** (15 have none). Every one of the 742
entries carries **exactly the same five keys** — no sparse entries, unlike goals — and the graph
shape is exactly two kinds:

| Kind | Count | Shape |
|---|---|---|
| "goal A done → add goal B" | 435 | `m_goalsAND` length 1, `m_goalsToAdd` length 1 |
| "goal A done → complete the quest" | 307 | `m_completeQuest: true`, `m_goalsToAdd` **empty** |

One single entry corpus-wide has 5 AND conditions. **`m_goalsOR` is empty in all 742 entries and
`m_requiredORCount` is `1` in all 742**, so the corpus contains **zero OR dependencies** and the
307 completing entries are precisely the 307 with no targets. Zero entries reference a goal absent
from `m_goals`. Reachability from `m_startGoals` holds for 317 quests; **5 do not** —
`WC-CYCLOPS-MAIN-002` (6 goals), `WC-TRITON-MAIN-008` (4), `WC-TUT-C03-001` (19), `WC-TUT-C05-001`
(5), `WC-TUT-C08-001` (1) — so the warning banner has real data behind it, and 2 quests have logic
with no start goals at all.

Consequence, recorded honestly: the **dashed OR edge, a multi-prerequisite entry,
`m_requiredORCount > 1` and the `unsatisfiable-or-count` finding are fixture-only**. They are
labelled as such in the model's header, the unit fixture and the tier-1 spec, and no comment claims
the corpus exercises them. The tier-2 pass confirms it live: 0 dashed edges on a real quest.

## 7. Decision D61 (recorded in `docs/plan-overview.md`)

- **The dependency.** The plan (§3.5) and `spec-ui-design.md` L344 name a **React Flow** canvas,
  but D25's owner-approved list names only `dagre` for this task. The detailed spec wins (D29's
  standing rule), so React Flow was installed exact-pinned and the omission is flagged for the
  owner in the phase-3 PR rather than silently absorbed.
- **The containment, because the cost was real.** Measured before containment: the single app chunk
  grew 574,044 B → 868,865 B raw and **+95.1 kB gzip**, all of it on the entry of every route, and
  Rollup's >500 kB warning began firing. The story then contained its own cost behind
  `React.lazy`: the entry chunk is back to 575.86 kB / **gzip 177.23 kB** (pre-story 574.04 kB /
  176.16 kB, so the story's net cost to every route is ~1.1 kB gzip) and the flowchart lives in a
  293.59 kB / 97.76 kB gzip chunk that the live stack proves is fetched **only** when the tab is
  opened.
- **The validator/banner split.** The model returns structured findings and never the banner's
  copy; the UI renders the spec's verbatim sentence only for the kinds the sentence is pinned to
  (`disconnected-goal`, `cycle`, via `BANNER_FINDING_KINDS`) and a neutral headline plus a details
  list for the rest (duplicate names, unknown references, unsatisfiable OR counts). The tier-2 pass
  shows both states on real data, including why the distinction matters: deleting a goal whose
  dependants are themselves start goals produces `unknown-goal-reference`, not a stranded graph.
- **"Disconnecting" = the node menu's Delete.** Removing an edge cannot disconnect anything — an
  emptied condition list fires vacuously — so the AC's clause is the goal-delete path, and the
  tier-1 spec pins that an edge-delete leaves the graph reachable with the banner **absent**.

- Creating a **new edge by dragging between handles** is wired and unit-tested (12 cases) but was

  second cross-tab channel, so it is reported rather than silently skipped.

  the JSON panel, not to disk; the save pipeline is D49's contract and this story does not touch it.
