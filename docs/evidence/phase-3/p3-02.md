## 4. The json5 question (a lead design call made mid-story)

The first draft of `shared/document.ts` imported `json5` for a text-taking `loadDoc`. I directed its
removal, for measured reasons:

- `client/tsconfig.json` compiles `["src", "../shared"]` with **no `esModuleInterop`** — the interop
  workaround existed only to serve that import;
- the client **never parses JSON5** (no `json5` reference under `client/src`; the editor receives
  parsed JSON from the API), yet stories 3.3–3.10 will import these primitives, so `json5` (96 KB in
  `node_modules/json5/lib`) would ride into the client bundle for an unreachable path;
- a lenient text parser already exists server-side (`server/src/services/sync/json.ts` +
  `parseJsonLenient`), and the test imports `json5` directly.

Result: `loadDoc(document: unknown)` (identity + `TypeError` guard), `shared/document.ts` imports
nothing, and the client bundle is **byte-identical** to the pre-story build
(`495813 B assets/index-CPmYBVzB.js`, same content hash; `grep -rl JSON5 client/dist` → nothing).

| Falsification | Observed |

| `serializeDoc` sorts every object's keys | real corpus `failures=322`, every message `<root>: key order differs (… vs …)`; exactly the 2 ac1 sweeps failed **while `isDeepStrictEqual(source, sorted)` is true** — i.e. deep equality alone would have passed a reordering writer, which is why order is asserted separately |
| `setAtPath` also writes a probe key on every ancestor | 5 tests failed (both ac2 suites + the primitive test), everything-else check reporting the injected key outside the mutated path |

**Lead's structural re-check** of the mechanism behind #1/#2 (`p3-02-independent-verify.txt`):

```
null-dropping writer  -> isDeepStrictEqual(src, reparsed) = false  (caught)
key-reordering writer -> isDeepStrictEqual(src, reparsed) = true   (deep-equal alone MISSES it)
```

Honest gaps in this section: falsification #2's *mutated-state* md5 was not captured (only the
before/after reverts), and #3's injected ancestor key makes the first reported path `<root>` rather
than the single sibling the harness's own sibling-touch test constructs.
