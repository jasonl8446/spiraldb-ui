## 3. Measured corpus facts this story rests on

- **381 result nodes** in the 322 quests, all 14 types present: ResDropTable 317, ResLearnSpell 21,
  ResAddDynaMod 13, ResGiveSpell 10, ResDrawHand 8, ResPostEvent 3, ResAddSpell 2, and **exactly one
  each** of ResAddHealth, ResAddMana, ResModifyEntry, ResTeleport, ResPlaySound, ResDespawn, ResWait.
  Seven of the fourteen forms therefore have a single corpus instance; ResDropTable is the only
  common one. Coverage claims are labelled accordingly.
- The wrapper is **`{"m_results": [...]}` with no `$type`**, at four homes (all 100% present:
  `m_startResults` 322, `m_endResults` 322, per-goal `m_completeResults` 772, `m_activateResults` 772)
  plus the 18 `m_tallyCounter.m_tallyResults` slots — 2206 wrappers in total.
- **One key order per type**, and the spec's prose order is not always the corpus's:
  `ResModifyEntry` is the measured case (`$type, m_entryName, m_isQuestRegistry, m_value, m_questName`).
  Unlike p3-06's ReqHasEntry, **no type carries an undocumented key** — field presence matches the
  domain reference exactly for all 14, and the two fieldless types are `$type`-only.
- `m_router` is a plain **untagged** sub-object with the fixed 6-key order
  (`m_locX, m_locY, m_locZ, m_routingType, m_useLocation, m_useTriggerLocation`).
- `ResLearnSpell.m_requirements` is present in **21/21** (the spec calls it optional) and is an
  **untyped** wrapper containing one `ReqSchoolOfFocus` leaf each.
- **Friendly-name resolution, measured against the live tables**: `ResLearnSpell.m_templateID` →
  spells 16/16; `ResGiveSpell.m_spellID` → spells 10/10; `ResAddSpell.m_templateID` → spells 2/2;
  `ResGiveSpell.m_templateID` → npcs 2/2; `ResDespawn.m_templateID` → npcs 1/1;
  `ResDropTable.m_tableName` → drop_tables 317/317; zones 2/2 and 1/1.
  **`ResDrawHand.m_templateID` does not fit a single table: its 8 distinct values resolve 6 in
  `spells` and 2 in `npcs`, and none resolves in both** — a single-source dropdown (which is what
  the domain reference implies) would leave six of eight real values nameless. The field is
  therefore declared dual-source and miss-safe, and tier-2 §3 proves it live.
- Hazards honoured (D59c): `ResModifyEntry.m_questName` is `""` in its one node and
  `ResAddDynaMod.m_zoneName` is `null` in 7 of 13 and `""` in 2 — an empty or null reference
  produces **no lookup request** and the key is never rewritten with a placeholder.

type-count ties in the wrong order.

## 7. Decisions (D63, recorded in `docs/plan-overview.md`)

- **The five containers, from tab ownership rather than invention.** All four homes' owner labels
  are `Results` (`lib/quest-info.ts` L192-193, `lib/quest-goals.ts` L405/L410), so the Results tab
  mounts them — and it also mounts the **5th container, `m_tallyResults`**, because D60(d) named
  task 3.7 as its owner ("if 3.7 does not pick it up it stays a documented gap"). The tally slot is
  guarded to the 18 goals whose `m_tallyCounter` is an object, because a `set` under a `null`
  parent would be rejected by the primitives; the other 754 goals get an honest note.
- **`ResDrawHand.m_templateID` is dual-source and miss-safe**, with a UI-only source toggle
  (never written to the document) that defaults to whichever table the value resolves in and to
  `npcs` (the domain reference's own claim) when neither does.
- **A class change / a new node uses the type's corpus order**, and the router is written whole on
  first edit (the primitive never invents an intermediate object), which appends the key last on an
  existing node — a measured consequence, pinned by the spec.
- **No `moveResultEdits`**: result order is execution order and the spec has no reordering
  affordance; flagged for Phase 5 if wanted.
- One stated limit carried over from p3-06: if a user deletes the root requirement wrapper and
  re-adds it through the shared tree, `initializeTreeEdits` writes a *typed* `RequirementList` —
  p3-06's recorded rule, deliberately unchanged here.

## 9. What this story did **not** prove

- No pixel inspection of the two screenshots (no image input in this model).
- Coverage: **7 of the 14 forms have exactly one corpus node**, so their fixture values are
  synthetic; only the seeded real shapes are corpus-bearing (the `ResModifyEntry`, the null/empty
  zones, the `ResDrawHand` split, the router sample). ResDropTable is the only common form.
- `m_teleportType` (`TELEPORT_STATIC`) and `m_routingType` (`ROUTING_ACTOR`) option lists rest on
  **one measured value each**; an unlisted value is preserved and selectable, not rewritten.
- New-node defaults for single-sample fields (`m_secondsToWait: 0`, `m_reinteractTime: 0`,
  `m_value: 0`) are neutral choices rather than measured majorities; `m_maxRolls: 1` is the 314/317
  majority.
- The dual-source toggle's default can flip from `npcs` to `spells` once the spells list finishes
  loading — a derived-UI artifact, never a document write, stated here so it is not mistaken for
  data loss.
- No Save was pressed in tier-2, so "saved" means the live document and the JSON panel, not a file;
  the save pipeline is D49's contract, unchanged.
- 768px/mobile was not re-checked for this tab.
