## 3. Measured facts this story rests on

The authoritative survey (recorded in full in D60): 772 goals across 311 of 322 corpus quests.
759 carry all 24 base fields; **13 are sparse** — 5 with 14 keys, 8 with 15 — and all 13 come
from `questtemplates_WC-CYCLOPS-MAIN-002.json`, an *extracted* quest. So "add a field the
schema nullishes" would silently rewrite 13 real goals, and the editors were built to
**preserve absence** (D57): the sparse-goal tests fail if any editor pads them.

Goal **type** coverage: 322 quests hold 5 distinct goal `$type`s, each mapping to one spec, and
`unmodelledGoalKeys` is empty for all 772 goals. The `($type, m_goalType)` pairing is **not**
1:1 — Persona→`GOAL_TYPE_PERSONA` 405, Waypoint→`GOAL_TYPE_WAYPOINT` 194, Bounty→
`GOAL_TYPE_BOUNTYCOLLECT` 96 or `GOAL_TYPE_BOUNTY` 4, Scavenge→`GOAL_TYPE_SCAVENGE` 43 or
`GOAL_TYPE_USAGE` 4, AchieveRank→`GOAL_TYPE_ACHIEVERANK` 26 — so creation writes the majority
pairing and an existing minority value is left alone (D60(a); tier-1 covers the Bounty case).

`m_startGoals` holds goal **name** strings: 306 of 322 quests have a non-empty array and the
corpus contains no dangling reference. The editor's delete deliberately does **not** cascade
into it (task 3.9 owns that), and a goal with no name cannot be made a start goal.

Three fields have no closed list to offer, and each control is miss-safe rather than invented:
`m_zoneTag`/`m_proximityTag` resolve for 112 of the 149 distinct zone paths in the corpus;
`m_personaName`'s 8 distinct values resolve to 0 of 23,033 `npcs.name` rows and 0
`string_table` keys; `m_bountyType` has one measured value (`BT_MOB_KILL`).

## 7. Decisions this story made (D60)

D60 is recorded in `docs/plan-overview.md`; it pins (a) the non-1:1 `$type`↔`m_goalType`
pairing and the majority-on-create rule, (b) the 13 sparse extracted goals that must not be
padded, (c) the three miss-safe reference controls, (d) the read-only complex fields —
including **the one plan deviation**: `m_tallyCounter` is named once in the plan's Bounty/
Scavenge field list, but every measured value (18/772) is a nested object whose
`m_tallyResults` is a results container that task 3.7 owns, so it is surfaced read-only with
`owner: null` rather than edited here — a documented gap if 3.7 skips it, (e) the string-table
key hazard on `m_goalTitle`, (f) the two pinned dnd-kit packages, (g) the `panels` map, (h) the
badge showing the `$type`'s TypeName (consistent with p2-07), and (i) the tier-1 timing/locator
corrections below.

One further measured defect is recorded rather than fixed: `shared/quest/goals.ts`'s header
claims all 24 base fields are present on every goal. It conflates *present with a null value*
with *absent*; the schema is `.nullish()`, so the claim never breaks validation. It is a
comment, not behaviour (D60(b)).

## 8. Execution-model note: the executor dispatches died

Three `omd-agent-executor` dispatches covered this story and **none** returned a closing
message — the same harness-side connection failure the owner confirmed and fixed during p3-03.
The first two left usable work (the model, then the component and its tests); the third left a
tier-1 spec with 6 failing assertions. Closing the story fell back to the lead, which is
recorded here rather than hidden: the lead diagnosed and fixed the spec's four failure classes
(the summary's colon-space, the two drag timings, the zone locator, and the clipboard race),
corrected the raw-fields disclosure's over-claiming counts, re-ran the gate, and produced the
tier-2 evidence. Blaming the failures on the agent's work would have been wrong: on the real
stack both drag sensors reorder correctly, and the badge text convention was already right.

The four spec-side corrections, in the order they were found:

| Symptom | Real cause | Fix |
|---|---|---|
| 2 assertions expected `Zone: path` | the card's summary is a `<dl>`; the colon-space the design ASCII draws is a **flex gap**, so `textContent` has no space | assert label and value as a pair (`summary(label, value)` → `/label:\s*value/`) |
| keyboard reorder produced no move | Space/ArrowDown/Space pressed within ~50 ms; the sensor announces the lift before it has armed arrow handling | await dnd-kit's own live-region announcements, plus one settle between steps |
| pointer drag landed one index further than asserted | the move ended on the second card's bottom edge, which `closestCenter` reads as the third card's half | aim at the card's centre (verified live at both positions) |
| `locator.fill` timed out on the zone search | the search box is `cmdk`'s input: it carries `role="combobox"` + the right `aria-label`, but `getByLabel` does not resolve it | address it by role |
| `Unexpected end of JSON input` after a drag | `copyPanelDocument` read the clipboard before the Copy handler's async write | poll until the JSON is on the clipboard |

  pipeline's formatting-only diff contract is D49's, unchanged by this story.

  stays a documented gap.
- The 5-type add flow is proven at the model + UI + live-document level; it was not exercised
  against all 322 corpus quests at once (the model-level sweep is the corpus-wide evidence).
